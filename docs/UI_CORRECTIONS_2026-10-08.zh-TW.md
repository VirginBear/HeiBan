# 2026-10-08：文字捲動與工具列修正

## 問題與原因

使用者在文字框／便簽的輸入區使用滾輪時，畫布同時放大縮小。

`CanvasView` 原本安裝 `ScrollWheelMonitor`，其局部 NSEvent 監聽只確認事件位於畫布大小的區域，未確認事件目標是否為文字輸入區或其他可捲動面板。它先呼叫 `handleScrollWheel` 改變畫布，再回傳原始事件，讓 AppKit 繼續捲動文字；直接在原生畫布上亦存在監聽與 `PointerView.scrollWheel` 重複處理的可能。

## 修改

- 移除 `CanvasView` 的全區域滾輪監聽與不再使用的 `ScrollWheelMonitor.swift`，讓 AppKit 將滾輪交給游標下的文字／面板或原生畫布。
- `NativePointerSurface.PointerView.scrollWheel` 在文字編輯期間直接停止畫布操作，涵蓋一般滾輪、精確觸控板捲動、Shift 平移與指標位於編輯框外的情況。
- 核心 `handleScrollWheel` 也保護文字編輯狀態，避免其他呼叫來源誤改畫布。
- 原生及核心放大手勢入口同樣保護文字編輯狀態。完成或取消文字編輯後，入口自然恢復；不更改文件內容、縮放上下限與既有筆刷尺寸換算。

- 文字框貼入 20 行內容，捲軸從底部到頂部，畫布仍顯示 100%；在頂端繼續捲動及移到編輯框外也未改變縮放。
- 便簽貼入 20 行內容，輸入區上下捲動時畫布維持 100%，沒有跟著縮放。

## 工具列拖曳、停靠與自適應長度

### 原因

- 手柄採用隨工具列移動的區域座標；每個事件分別更新 BoardEngine 的 offset 寬與高，拖曳同時觸發整個觀察引擎的介面更新。
- 顯示寬度上限固定為 800、高度上限固定為 700，邊界限制卻按 420 的假定尺寸處理，與實際工具內容及可見尺寸不一致。
- 放開時以工具列中心判定停靠，長橫列難以靠到左右邊緣；選單停靠亦重新呼叫自動判斷，可能覆蓋指定位置。

### 修改

- 在工作區命名座標空間取得穩定拖曳位移，起始中心只記錄一次。拖曳中的位置／候選邊緣留在 ToolbarView 的本地狀態，放開後才保存引擎位置。
- 拖曳期間保持原方向並停用位置隱含動畫；放開到邊緣時依手柄位置切換方向，88 pt 內顯示直排／橫排停靠區。離開停靠後浮動保留原方向。
- 手柄獨立於工具捲動區，改用確實可顯示的三條線圖示；橫向與直向內容分開量測，包含各按鈕、分隔線與選單的實際尺寸。
- 工具列以內容長度加手柄／內距計算，再限制在視窗可用範圍。空間不足時只捲動工具區，位置限制使用真正的可見工具列大小。
- 四邊停靠選單直接指定方向與位置，不再二次自動判斷；位置及浮動方向寫入原有偏好設定。
- 右側停靠時屬性書籤向內移，避免遮住直向工具按鈕。

### 建置與實際查看

- Release App bundle 建置成功；`git diff --check` 通過。原有 SDK 搜尋路徑及未使用變數警告仍存在。
- 使用獨立作品庫／bundle 的暫存預覽，實際查看手柄拖到左邊、右邊與上方會對應切換方向；新版內容尺寸量測後左側直排及上方橫排貼合按鈕長度。
- 選單「靠下 · 橫向」直接切換到下方；在畫布內放開可保留浮動位置，完整工具仍可見。
- 未新增或執行自動測試；未量測逐幀拖曳耗時、長文件效能。此次視窗縮小操作未改變預覽視窗大小，因此不把小視窗溢出捲動與所有尺寸的排列列為已完成實機驗收；A12 保留該驗收項目。
- 暫存預覽關閉後清除，正式作品庫不受影響。
