## 開發範圍與現況

只修改 Windows 原生 C#／WinUI 3／Win2D 與 Windows 核心及測試。Mac 分析文件作為操作參考，不要求 Antigravity 修改 Mac 或 Web，也不引用 Swift／React 執行碼。維持 JSON 契約、原創品牌及圖釘。

preview.4 已有 A／B 端點、圖片八向縮放／旋轉、選取形狀色彩、上方作品列收合及尺邊／兩端支點。這些應保留並回歸驗證，不重新當作待移植功能。

截圖的新協調器與共用圖片置入入口已出現在目前原始碼，但既有 preview.4 發行包不因此自動包含新功能；文件的「完成／測試通過」不能代替當前來源的 WinUI 建置與實機驗收。

## W-V00 原始碼審查發現：封裝前必修

目前 `MainWindow.Input.cs`／`MainWindow.xaml.cs`／核心 `ScreenshotCaptureCoordinator.cs` 的問題：

1. **約 2.5 秒誤取消**：250ms 計時器持續累加 `_activationCheckCount`，以 `AppWindow.IsVisible` 判斷取消。主視窗在剪取浮層下仍可能可見；可見不等於已回到黑板，因此較慢框選會提前取消。改成明確的截圖啟動、失去啟用、回到視窗及結果／取消狀態；不可用可見性或固定幾個 tick 推斷取消。
2. **讀取完成後未重驗作品**：`TryConsumeScreenshotResultAsync` 在取得圖片串流前先 `Complete`，接著有多個 `await`。期間切作品／頁面，請求已清除，後續 `ApplyImageInsertionAsync` 卻讀取新的目前文件。必須在每次非同步解碼完成後、真正 `Begin/Add/Commit` 前，重新核對請求／作品／頁面與視窗有效性；撤銷須一直有效到文件提交。
3. **剪貼簿新圖片來源未被證明**：版號變更只排除舊內容，不能證明新 Bitmap 是該次截圖。外部剪取介面上的 Esc 也不一定進入黑板 `Root_KeyDown`。需核對可用的 Windows 官方結果／取消回傳方式；如保留剪貼簿方案，必須實測取消、重新複製圖片、剪取工具版本差異與回傳順序，不能靠版號就宣稱「絕不誤貼」。
4. **逾時狀態未正確結束**：`IsCapturing` 在逾時時直接為 false，watch tick 最前面便停止並返回，後面的 `IsExpired`／Cancel 分支無法到達。應先處理作用中請求的逾時，再決定是否停止；狀態與提示一致，清除請求及事件。
5. **圖片比例可能被最小尺寸破壞**：`ApplyImageInsertionAsync` 分別對寬／高 `Math.Max(24, …)`，細長截圖會改變比例。以單一縮放因子處理原圖比例與可用範圍；最小操作尺寸可用把手命中範圍處理，不要獨立拉寬／拉高圖片。
6. 同步更新截圖工具提示，目前仍寫「再貼上或拖入」；加入慢速框選、解碼失敗、重入、切情境、逾時的測試。不要只測核心的手動 `Cancel` 就宣稱 Windows 剪取工具取消流程已通過。

## 實作邊界與交付內容

- 目前 `EditorSession` 是單一 `SelectedId`，工具列在 `BuildChrome` 固定建構，快速面板各自開 Flyout，圖釘清單沒有搜尋。以這些實際缺口實作，不假設 Windows 已有 Mac 的偏好、快速列或多選協調器。
- 工具／視窗偏好寫入 `DocumentSessionManager.DataDirectory` 下的 `Settings`，安裝版／Portable／開發隔離皆遵循現有資料路由。不要把 UI 排序、HUD 或選單狀態塞進作品 JSON。
- 抽共用命令／設定面板生命週期與適當的純 C# 偏好／HUD 核心，避免繼續把所有邏輯加進 `MainWindow.Input.cs`。不要為可逆的排版微調建立大量鏡像測試；請求狀態、幾何、偏好保存、交易與資料往返應有必要檢查。
- 保留原有三種畫布、中文字輸入、自動保存、逐點形狀、尺規、圖層、右鍵及快捷鍵；兩種橡皮擦只處理筆畫／幾何，不刪圖片、文字、便簽或圖釘。
- 圓規、思維導圖、膠帶、雷射、計算器、完整富文本、PDF／SVG、帳號／雲端同步、觸控／筆壓新系統不納入本批。
- 不清理其他未提交變更，不覆寫或刪除使用者作品。實機測試用 `HEIBAN_WINDOWS_DATA_DIRECTORY` 指向專用暫存資料庫。
- Antigravity 交付：修改檔案及摘要、W-V00–06 各項完成／待驗收狀態、實際執行的指令／結果、測試文件與實機操作紀錄、剩餘問題。只標示有證據的結果。
