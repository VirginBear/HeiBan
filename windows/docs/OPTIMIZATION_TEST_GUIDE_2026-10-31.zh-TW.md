# 1.0.18 優化候選：實機測試指南（2026-10-31）

## 使用哪一份

本批最終免安裝標籤為`optimization-final-2026-10-31-r1`，維持1.0.18。舊`ponytail-2026-10-31-r2`及FD-r3是較早階段，保留紀錄，但本次驗收請使用最終標籤。

完整解壓ZIP後執行資料夾內HeiBan.exe；使用本資料夾自己的Data。以作品副本測試，舊版作品與商店版保留。若要測自己的大作品，先從舊版匯出，再匯入新版；不需要解除安裝商店版。`PracticeFiles/practice-100.heiban`與`practice-5000.heiban`是程式產生的100／5000物件測試作品，可在首頁「匯入」載入，不含私人作品。

## 建議照此順序，約15～20分鐘

| 項目 | 你要怎麼測 | 成功標準 |
| --- | --- | --- |
| 1. 開啟／顯示基礎 | 開空白筆記畫幾筆，回首頁，再開同作品；另外開螢幕畫布 | 畫布、筆畫與縮圖可見；沒有空白畫布、閃退或錯誤。這是前提，未過先停止其他驗收。 |

| 3. 擦除正確性 | 畫交叉筆畫、旋轉形狀、長直線／延伸線；鎖定其中一件、隱藏另一件，再擦。像素模式只擦筆畫一小段，按Ctrl+Z，再Ctrl+Y；筆記本切其他頁查看 | 只有實際接觸且可擦的物件／線段改變；鎖定、隱藏及其他頁內容不變，沒有遠處誤刪。局部擦除留下兩側筆畫，順序不亂；一次Ctrl+Z還原整次拖曳，Ctrl+Y重做。 |

| 5. 筆刷一致 PT-03 | 一般與螢幕畫布各開筆刷，調粗細0.5、6、64、128，透明度0%、50%、100%；選常用色／新增／移除；以系統100%、150%、200%縮放重開測試 | 兩畫布都能選相同範圍，不會在螢幕畫布卡在32。數值／實際筆寬對應，DPI改變不造成多乘／漏乘倍率。0%筆畫不可見但可用Undo移除；50%半透明。常用色兩畫布一致且重開保留；筆色與活動色線相符。 |

## 如何記錄「仍然卡」

1. 先正常關閉這份新版。
2. 在最終試用資料夾雙擊`Capture-InputLatency.cmd`啟動有採樣的版本。以同一作品／相同縮放重做問題20秒，不要在採樣中切其他程式或長時間閒置。
3. 正常關閉HeiBan，資料夾會產生`input-latency-*.json`。提供該JSON，加上「一般／螢幕畫布、工具、物件／像素模式、何時卡（按下／移動／放開）」；可附短影片。
4. 同機舊版若有相同採樣入口，以同作品副本與相同操作錄另一份。比較需同解析度、DPI、裝置及縮放；不能拿另一台電腦比較。

JSON中的PointerMove／CanvasDraw等是CPU處理或提交時間；EraserApply是背景工作時間。P95代表95%的樣本不超過這個值，適合看偶發停頓；它不等於鼠標到螢幕出光延遲。目標是兩份一致性檢查全過、動作跟手、主執行緒長停頓與背景追趕降低；目前沒有宣稱已量到固定FPS或50ms端到端。

## 商店包減重 PT-06：獨立驗收

最終實驗標籤為`optimization-final-fd-2026-10-31-r1`，只更改Windows App SDK部署方式，.NET仍自包含，免安裝版仍完整自包含。正式10/29商店包不變。

目前你先測免安裝版即可。FD候選是未簽章送審結構，不是可直接雙擊安裝的試用包；不要為測它解除現有商店版。正式採用前，要在乾淨的x64及ARM64測試環境，經可用的測試簽章／Store測試通道驗證安裝、runtime取得、啟動與舊版升級。

成功必須同時滿足：

- 候選本體比原包小，manifest宣告正確的Microsoft Windows App Runtime依賴，必要PRI／十語／法律文件完整。
- 沒有手工亂刪DLL；相依Runtime確實提供被移出的功能。
- 沒裝開發SDK的機器仍能正常安裝、首次啟動、一般／螢幕畫布、聲音、圖片／文件交換與重開保存。
- 由舊商店版升級後作品及設定保留。App本體與首次需下載的Runtime大小分開計算，不能把本體縮小百分比說成總下載量等比例縮小。

安裝／升級與實機項目尚未由助手執行，未通過前不把FD候選當正式上架包。
